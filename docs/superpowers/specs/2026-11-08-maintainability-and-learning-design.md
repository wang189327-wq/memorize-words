# Memorize Words：可靠存储与复习升级设计

状态：用户已于2026-11-08确认并授权按本方案执行；实现与验证见docs/verification.md。

## 已确认的目标

用户要求按以下顺序完善上轮评估中的问题，并使其他开发者容易理解和修改：

1. 文档一致性、Fork配置检查、CSP。
2. 实测保存性能，再拆分词库与学习记录、逐条保存复习事件。
3. 增加到期复习。
4. 网页离线、可选加密备份、开源项目展示。

每完成一个阶段汇报一次，保留已有四页、四种练习、手动选词、收藏、手动云同步及学习顺序。私人词书、学习记录、账号配置和签名私钥不进入公开项目。

## 实现路线与尚待确认的选择

- 推荐渐进改造现有JavaScript/Java工程：每阶段独立检查与提交，失败可定位、回退；沿用现有界面和公共接口。整体重写框架会扩大兼容风险，不采用。
- 推荐复用固定版本、MIT许可的ts-fsrs，而非自行实现算法或把固定间隔包装成智能调度。该算法选择是实施建议，需用户确认。
- 对新版本建议使用1.1 / versionCode 2，不覆盖已发布的1.0 / code1或其APK。包名保持cn.ielts75.app，正式签名保持原签名。Fork仍须自己的应用ID与签名。
- 推荐将FSRS评分事件独立完整保留，50000条上限仅用于现有练习统计历史。评分事件不随统计裁剪，否则无法可靠重建跨设备调度；这项数据保留策略需用户确认。将来需要压缩时另设计兼容迟到事件的检查点，本轮不偷偷压缩或丢弃评分。

## 阶段一：维护入口及资源策略

修改F盘总入口中残留的org.wordmemo.app / 1.4.0旧描述；项目README及生成资料读取app.config.json，历史文档明确标识历史版本。

新增独立配置检查脚本，供本地命令及CI共用。CI通过GITHUB_REPOSITORY识别是否原仓库：非原仓库却启用原更新地址或原Release地址时失败；配置自己的渠道或关闭更新后通过。主项目包名沿用不是漏洞，不借此再更换包名。检查不能限制Fork维护者自行修改代码。

HTML前部添加meta CSP；脚本默认仅同源，不使用unsafe-eval。明确封面data URL、备份blob URL和云同步连接需求。自部署支持用户填写HTTPS服务器，不能把connect-src锁死在原维护者的服务器，也不能宣称CSP已限制所有网络目的地。策略中每项允许范围写明理由，并在真实浏览器测试导入导出、主题字号、同步和WebView资源加载。meta CSP不能替代完整HTTP响应头能力。

策略基线：default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self' https:; worker-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'。style允许范围用于现有动态主题和字号；connect-src的HTTPS允许范围用于自部署服务器，不能通过后加meta来放宽已生效的更严格策略。不把脚本unsafe-inline一起开放。实际测试发现必要兼容差异时记录原因。

## 阶段二：增量保存与迁移

先记录基准：6张原创卡与5470卡规模，分别测试0、5000、50000条复习事件；分开记录验证、序列化和写入耗时。公开测试只使用程序生成的原创合成数据，私人全库仅本地测量。不预先承诺具体提速倍数。

存储结构采用浏览器IndexedDB和Android SQLite事务，按职责拆分：

- books：活动词库、修订、封面；仅导入或更新词库时写入。
- learned：每词首次学习日期。
- review_events：以eventId去重的复习事件，逐条插入。
- favorites：收藏及取消标记。
- metadata：学习安排、当前词库、迁移版本等少量状态。
- schedules：第三阶段加入的可重建调度缓存。

页面使用清晰的提交命令，经统一存储入口提交。普通学习、收藏、复习不再重复序列化词库，也不在每次点击时校验整本书。完整验证放在导入、迁移及恢复入口，单次命令校验影响字段。成功提交事务后更新页面状态，失败不前进；避免把等待保存期间的状态先展示成成功。

旧schemaVersion=1和Android learning-state.json可迁移。先在新存储中完整提交并校验记录数量、关键字段，再切换读取入口；迁移中断可重试，不删除唯一有效数据。旧存储只有确认迁移成功后才清理。导出仍提供完整、独立可恢复的备份，不要求用户持有多个增量文件。SQLite/IndexedDB内部日志不等同于保留多个旧学习版本。

新增schemaVersion=2完整备份，明确包含deck及进度、评分事件、调度参数版本；独立旧格式适配器负责schema1读取，不承诺旧程序能读取新版备份。字段映射必须保留cursor、learningPlan及drill、favoriteChanges、bundledRevision等现有有效字段。缺eventId的旧历史仅在首次迁移时分配并持久化稳定ID，不在每次同步时按数组位置重新生成。新存储迁移完成前，禁止提前执行旧加载逻辑中的localStorage清理。

复习历史仍遵守已有50000条上限，不因迁移额外扩大。保留并单独标识旧算法调度的初始化状态，不能假造旧记录缺失的评分。

以上“复习历史”专指现有results统计数组；新FSRS评分事件是独立日志，按前述推荐完整保留。其磁盘用量和备份体积需显示，不得以超过旧50000阈值为由静默删除。

## 阶段三：到期复习与跨设备调度

复习页新增“今日到期”，按到期时间选择词卡，用户仍可选择练习方式和数量；不移除随机、学习日期或收藏范围。没有到期词时说明状态，允许使用原手动复习。

调度封装为独立纯规则模块，页面不直接操作算法字段。使用固定参数与版本的FSRS，每次评分保留事件ID、卡片ID、UTC时间、练习方式和again/hard/good/easy评分；UI使用“不记得、困难、记得、很熟悉”。自动判分的题目不能把“正确”直接等同于“很熟悉”；答错或查看答案后记为不记得，正确后的反馈由用户选择。

新词学习中的7/18词拼写保留为当次学习巩固，不把同一会话多次答题自动当作多次跨日长期复习；长期调度事件须明确标记。旧记录有correct/at但没有四档评分，只保留历史，旧已学词进入待初始化的到期队列，不伪造个性化训练参数。

基于不可变评分事件确定性重建每词调度，先按UTC时间再按eventId排序；重复同步不增加复习次数。测试时区变化、时间相同、离线两台设备同时评分、未来异常时间和重新导入备份。

事件携带书籍命名空间、规范ISO UTC时间与算法/参数版本。同eventId内容冲突返回409，不能后到覆盖。异常未来时间明确拒绝或隔离，不按各设备“当前时间”重写事件。支持多客户端同时写时，事件持久化与调度缓存须通过事务或可重建标记保持一致。

云端增加独立版本的评分事件接口/能力标志，不把新字段硬塞进旧接口。保留旧进度/收藏协议及旧客户端可用性。新客户端遇到旧后端时继续保存本地调度并明确提示“智能复习记录尚未同步，需更新后端”，不丢弃数据、不谎报全部同步完成。只同步进度与评分事件，不上传词书。提供更新后的FC部署包与升级说明；生产阿里云部署和真实账号写入未完成时不得标为已验收。

先检测能力，再按进度/收藏和评分分别记录同步状态，不能用单一成功标记掩盖评分未上传。评分按事件ID去重、分页传输，不在每次同步重传词书或全部评分。

## 阶段四：离线、加密与展示

PWA：manifest及Service Worker仅用于浏览器，安卓不注册Service Worker。应用外壳与示例资源离线缓存；用户词书和记录继续由IndexedDB管理，不依赖缓存保管。首次联网加载及缓存完成后才承诺离线启动，首次从未访问无法离线使用。禁止缓存登录凭据、云API响应和APK下载。缓存更新有版本清单，活动学习中不强制刷新，不清理学习数据库。验证子路径部署、断网重开、更新失败及旧缓存回退。

静态模块清单完整缓存成功才允许新worker接管；失败保留旧缓存，不在活动页面无条件skipWaiting。存储升级处理IndexedDB versionchange/blocked：提示关闭旧标签后重试；不在新数据库模式已提交后回退到无法读取该模式的旧应用代码。

加密备份：保留原明文JSON导入导出，新增可选密码备份。使用WebCrypto PBKDF2-SHA256派生AES-GCM密钥，随机salt和IV，每次导出不同；封装版本、参数及密文，不保存密码。密码双次确认，明确忘记密码无法找回。导入先校验封装大小和参数上限，解密、完整验证成功并经用户确认后才覆盖当前数据；错误密码、篡改或损坏均不能影响现有进度。密码参数集中定义并说明依据，不自行发明密码算法。

统一以UTF-8字节计算备份限制，同时考虑Base64膨胀，保证本版成功导出的文件可被本版导入。未完成流式大备份前，超过支持体积须在导出前明确报错。密码采用明确的UTF-8编码规则，不擅自trim或Unicode归一化；封装头作为认证附加数据保护。实际安卓WebView与浏览器分别验证中文密码和跨端恢复。

项目展示：原创示例界面截图、简短上手步骤、故障/功能建议模板、合适Topics；截图不含私人词书或账号。Star/Fork数量不是验收目标。不改已确认的桌面图标。

## 对开发者的交付

- 按存储、调度、备份加密、离线缓存分别建小模块，模块名说明职责。
- 公共函数写明输入、返回值、失败行为与调用示例；注释解释设计原因，避免逐行复述代码。
- 更新架构地图、数据格式与迁移说明、云端兼容矩阵和贡献指南；说明新增功能的主要修改入口。
- 可重建资源通过一个明确命令生成；固定依赖及算法参数，不把生成结果和源文件混作维护入口。
- 每阶段都有直接覆盖数据损坏/中断/重试的测试；不以镜像实现的重复断言充数。
- 最后打包公开示例版、更新清单、源码及云端部署包，核对SHA256，复制到F盘并刷新SOURCE_SHA256。个人正式交付如需切换新版须单独核对完整词库、封面及原签名，不能用公开示例包覆盖个人交付文件。
- 明确区分本机测试、远端CI、线上网页、安卓实体设备和真实阿里云测试。未完成的外部验收如实列出。

## 验收与范围

旧完整备份可恢复，学习日期、收藏取消标记、学习安排、复习历史不丢失；四个页面与原四种练习继续可用；记录保存失败不改变显示进度；断网缓存后重开网页可学习；加密备份能跨网页版/安卓恢复；已配置后端的新设备可重建同一调度；旧后端有明确兼容提示。

本轮不开发OCR、云端词书、多活动词库、多用户SaaS或后台每日检查更新，也不更换图标。服务端能力升级不等于擅自修改用户的生产云端配置。
